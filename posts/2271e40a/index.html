排查实录：Claude Code / Codex 调用 Gemini 报 429 (RESOURCE_EXHAUSTED) 假限流与绕过方案

发表于2026-09-13|更新于2026-09-18|AI

三、根本原因剖析

结合 GitHub 社区（CLIProxyAPI #5751）及社区二分法（Bisect）测试结论：

  1. Google 的特征指纹拦截：
    Google 的 Cloud Code Assist 网关（cloudcode-pa.googleapis.com）部署了 WAF/滥用检测规则。该网关专门针对非官方接入的各类 Coding Agent 做系统提示词静态文本特征匹配。
  2. 伪装假限流：
    当请求的 systemInstruction 命中黑名单词组时，网关**故意不返回 400 违规，而是伪装返回 429 RESOURCE_EXHAUSTED**，导致开发者误以为是账号配额或并发被风控限制。
  3. 已知的特征指纹库：
    • Codex：命中 You are Codex, an agent based on GPT-5.
    • **OMP (oh-my-pi)**：命中 <system-conventions> 与 RFC 2119: MUST, REQUIRED...
    • Claude Code：命中 Claude Code、Anthropic's official CLI 以及计费头 x-anthropic-billing-header。

四、解决方案：利用零宽字符混淆

由于这是基于静态子字符串/正则的 WAF 规则，绕过思路非常简单：在关键词中插入零宽字符（Zero-Width Space \u200b）。

大模型在 Tokenize 时对不可见字符具有天然的容错与泛化能力，语义完全不受损；但 Google 网关的精确字符串正则规则会被当场打碎。

五、总结

遇到第三方调用 Google / Antigravity 出现秒回 429 且与配额无关时，切忌盲目换号。

  1. 优先抓包：查看实际发向上游的请求体，定位客户端注入的硬编码 system 指令。
  2. 定位特征：寻找包含客户端名称、官方 CLI 声明、特定 XML 容器标签等唯一性短语。
  3. 中间件混淆：利用代理层插入零宽空格打破 WAF 匹配，是最省心、且完全不依赖客户端魔改的通用解法。
