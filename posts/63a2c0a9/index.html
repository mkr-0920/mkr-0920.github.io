现代代理技术栈详解：协议、传输与安全

发表于2025-06-20|更新于2026-08-09|network

三层结构

先把框架理清楚。一套代理配置基本就是三层叠起来的：

  • 协议：怎么加密、怎么打包、怎么验证身份。VMess、VLESS、Trojan 这些都是协议。
  • 传输：数据在网上以什么形态跑。裸 TCP，还是套进 WebSocket、gRPC 里。
  • 安全（伪装）：在传输外面再包一层，让防火墙看不出这是代理流量。TLS、REALITY 干的就是这个。

Xray、sing-box 这类核心的配置文件基本就是照这三层写的：挑一个协议，塞进一种传输，再加一层伪装。搞清楚每层各自在干嘛，看别人的配置、自己排错都会顺很多。下面一层层拆。

协议

协议是核心，决定数据怎么加密、打包、验身份。

Shadowsocks (SS)

最老的一个，说白了就是加了对称加密的 SOCKS5。轻、快、配置简单，网络没干扰时速度很顶。缺点是特征相对固定，现在单靠裸 SS 容易被识别和干扰。后来的 SS-2022（AEAD-2022）换了新加密和握手，加了重放保护，抗主动探测强了不少，现在给 SS 一般都是这个版本，老的 stream 加密早该弃了。

VMess

V2Ray 那套的老协议，比 SS 复杂，用 UUID 认用户，带多路复用。安全性够用，但它有个时间戳校验，客户端和服务器时间差太大就连不上，性能开销也比后面的 VLESS 大。现在基本被 VLESS 取代，新搭没什么理由再选它。

VLESS

VMess 的精简版，思路是把加密、验证这些活儿全甩给传输层（TLS / REALITY），协议自己只管转发，几乎零开销。所以它本身不加密，必须配 TLS 或 REALITY，裸跑等于裸奔。现在主流搭法基本都绕着它转，尤其是 VLESS + REALITY。它还带个 flow（XTLS-Vision），能缓解 TLS 里再套 TLS 被识别的问题，配 REALITY 常一起开。

Trojan

核心思路就一个：装成正常 HTTPS。服务器平时就是个普通网站，谁来都按网站回应，只有拿对密码的连接才走代理。主动探测的人看到的就是个正常 web 服务，伪装度很高。缺点是得自备域名和证书，性能比 VLESS 略重。其实和 VLESS + TLS 定位重叠，看习惯选一个就行。

Hysteria2

专门给烂网络设计的，底层是改过的 QUIC（HTTP/3 那套），走 UDP。靠自己的拥塞控制加暴力多发，在高延迟、高丢包的线路上速度能甩 TCP 一大截。代价是费带宽，网络本来就好时优势不明显；而且吃 UDP，运营商拿 QoS 限 UDP 甚至直接封 UDP 时就抓瞎。跨国、移动、卫星这类质量差的线路很合适。

TUIC

和 Hysteria 一个路子，也是 QUIC 走 UDP，主打低延迟和 UDP 转发，打游戏、语音这种对延迟敏感的场景用得多。优缺点跟 Hysteria2 类似，一样怕 UDP 被封。选它还是 Hysteria2 主要看线路和个人习惯，前提都是你的线路 UDP 得通。

AnyTLS

比较新的一个协议，专门冲着「TLS 套 TLS」去的——代理流量本身是 TLS，里面裹的用户流量又是 TLS，两层嵌套会在包长上留下能被统计出来的特征。AnyTLS 用一套灵活的填充（padding）把这种特征打散，另外自带多路复用减少建连开销。目前 sing-box、mihomo 支持。想要隐蔽、又不想折腾 REALITY 的可以留意。

传输

传输决定数据包在网上以什么形态跑，也是伪装的第一道。

Raw (TCP/UDP)

最原始，直接发。没额外开销、延迟最低，但也没任何伪装，特征最明显。一般是配合 REALITY 这种在安全层做伪装的方案用（VLESS + Raw(TCP) + REALITY 就是这么来的），单独裸用没什么隐蔽性。

WebSocket (ws)

把流量塞进标准 WebSocket 连接，看着像网页的实时通信。经典伪装手段，最大的好处是能过 CDN——把服务器真实 IP 藏在 Cloudflare 这类 CDN 后面，抗封锁、抗打。代价是多一点握手开销和延迟。

HTTPUpgrade

用 HTTP/1.1 的 Upgrade 头把连接升上去，特征像普通 web 服务。可以理解成更轻的 ws，省掉了 ws 自己那层帧封装，一样能过 CDN，是近两年比较推荐的 ws 替代。

gRPC

用 Google 的 gRPC 框架传，底层是 HTTP/2，流量看着像两个服务器之间在调 API。比 WebSocket 更现代，多路复用是天生的，弱网重连也好。同样能过 CDN，但部分 CDN 对 gRPC（HTTP/2）支持不如 ws，用之前最好确认下。

XHTTP

Xray 后来搞的传输（前身是 SplitHTTP），把上传和下载拆成不同的 HTTP 请求走，对 CDN 特别友好，很多 ws/gRPC 过不顺的 CDN 场景它能过，支持 HTTP/1.1、2、3。现在 Xray 里过 CDN 基本首推它。

mKCP

基于 UDP，用冗余数据换低延迟，丢包环境下比 TCP 稳，适合游戏、通话这种。缺点是特别费带宽（一直在多发冗余包），非必要不用。

传输安全（伪装）

这一层把流量伪装成正常东西，让防火墙认不出真实目的。

None

不加任何伪装，全靠协议自己的加密。现在的审查环境下基本就是裸奔，公网别这么用。

TLS

用得最多的。自己搞个域名 + SSL 证书，把代理服务器伪装成一个正常 HTTPS 网站，经得起时间考验、可靠。缺点是要买/续域名和证书，而且你那个域名如果是小众的、没什么真实流量，本身可能就成了特征点。

REALITY

Xray 搞的，可以理解成 TLS 的加强版，解决了「自购域名容易被盯上」这个问题。它不自己签证书，而是握手时借一个真实大站（比如 microsoft.com）的 TLS 身份，防火墙探测时看到的就是你在访问那个大站，就放行了；就算有人主动来连你的服务器，也会被转到那个真站上，露不出马脚。不用买域名和证书，配置还简单，是目前隐蔽性最高的方案之一，基本是 VLESS 的黄金搭档。

uTLS / 指纹

严格说这不算单独一层，是个补充。防火墙除了看流量，还会看 TLS 握手的指纹（ClientHello 长啥样，也就是 JA3）。代理软件默认的握手指纹要是和真实浏览器对不上，照样露。uTLS 就是拿来模仿 Chrome、Firefox 这些真浏览器指纹的，配置里把 fingerprint 填 chrome 之类就是干这事，TLS、REALITY 都会用到。

常见组合怎么选

不用记那么多排列组合，按场景挑就行：

  • 自建、追求性能和隐蔽：VLESS + Raw(TCP) + REALITY。现在最主流的搭法，快、隐蔽，还省了域名证书，能上就首选这个。
  • 要过 CDN 藏 IP：VLESS/Trojan + ws / HTTPUpgrade / XHTTP + TLS。走 Cloudflare 这类 CDN，服务器真实 IP 不暴露，抗封抗打，代价是延迟高一点、速度受 CDN 限。
  • 线路烂（高延迟高丢包）：Hysteria2 或 TUIC。前提是线路 UDP 得通，通不了就老实回 TCP 系。
  • 用机场：给什么用什么，自己没得选。大多是 SS-2022、VLESS+REALITY、Hysteria2 混着发，看客户端能不能全解析（sing-box、mihomo 兼容性最好）。

核心软件

协议传输这些最后都得落到具体软件上，常打交道的就这几个：

  • Xray-core：VLESS、REALITY、XHTTP 这些的娘家，功能最新最全，自建服务端常用它。
  • sing-box：支持的协议最杂（Hysteria2、TUIC、AnyTLS、REALITY 都有），配置统一，客户端服务端通吃，现在不少人拿它当主力。
  • mihomo（Clash.Meta）：Clash 内核的社区增强版，规则分流做得好，桌面和软路由上分流复杂的场景基本靠它。原版 Clash 早停更了，现在说 Clash 一般指的就是它。
  • Hysteria：Hysteria2 的官方实现，专协议专用。

配置上，服务端和客户端的协议、传输、安全三层必须一一对上，任何一层对不上都连不了——排错的时候就照这三层挨个核对。
