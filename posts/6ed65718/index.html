校园网IPv6漏洞

发表于2022-10-01|更新于2026-07-25|network

IPv6免费上网技术原理

⚠️ 重要声明：

本文旨在进行网络技术原理的科普与探讨。任何利用本文所述原理绕过校园网认证、计费系统的行为都严重违反学校的网络使用规定，可能导致账号封禁、网络权限收回等后果。请遵守规定，合规上网！

原理

先说清楚：这漏洞跟 IPv6 协议本身没关系，不是协议留了后门。根子在于很多学校对 IPv4 和 IPv6 是两套管法。

IPv4 那条路又老又挤，出口上认证、计费一整套伺候着，每个包都得查、都得记，流量超了还得多掏钱。IPv6 是后来才铺的，更新更宽，但铺的时候和管理初期，常常没在出口装认证和计费——可能是管理员没顾上，也可能是旧的认证计费设备根本不认 v6。所谓「IPv6 破解」，说白了就是想办法让流量别走那条又收费又要认证的 IPv4 老路，全挪到没人管的 IPv6 上。

这事集中在校园网是有原因的：国内 IPv6 这几年才大力推，教育网（CERNET）上得早、给的还是公网地址，而配套的认证、计费改造常常跟不上部署速度，一快一慢，窗口就留出来了。

两种形态

管理员的意识不一样，这漏洞也分两种。

形态一：认证前 IPv6 就是通的

最原始最彻底的一种，IPv6 通道完全没人看。认证之前，IPv4 被认证系统挡着上不了网，但设备照样能拿到公网 IPv6，直接访问外部 v6。原因很简单：认证系统（不管 Web 认证还是客户端）是老古董，只会盯着 IPv4 拦，对 IPv6 视而不见。

用起来分两种情况：目标站也支持 IPv6（Google、B 站这些），系统一般优先走 v6，直接就免费上了；目标只有 IPv4（某些游戏），就得找个中转——租一台校外的双栈 VPS，用校园网免费的 v6 通道跟它建 VPN，流量打包走这条免费隧道送到 VPS，再由它帮你访问整个互联网。

形态二：认证后 IPv6 不计费

更常见、也更棘手的一种：管理员把认证系统升级了，计费系统却没动。认证前 v4/v6 都上不了，正常登录后都能用；但一查流量会发现，只有 IPv4 记了账，IPv6 下的那几个 T 跟没发生过一样。

问题出在认证和计费脱了节：认证系统已经双栈感知，登录时把 v4、v6 两扇门一起开；计费系统还只认 IPv4，蹲在出口数 v4 的包，旁边流过的 v6 包压根没进它眼里。

为什么认证和计费会脱节

因为管 IPv4 和管 IPv6，实现思路上有根本区别。

认证：从管 IP 变成管设备。 IPv4 时代习惯给你分个内网 IP，然后授权这个 IP。到了 IPv6，一台设备有一堆、还频繁变化的地址，靠谱的认证就不能再盯着 IP，得直接管设备的 MAC，认证一过就放行这个 MAC 的所有流量。老式 Web 认证没完成这个转变，漏洞就来了；而 802.1X 工作在 IP 层之下，天生就是管设备的，双栈能一起管好——这也是为什么先进的认证方案不吃这一套。

计费：得整个重配一遍。 IPv4 的流量统计（NetFlow/sFlow）早就很成熟，管理员配起来熟门熟路。IPv6 底层技术相通，但得专门为 v6 再开一遍监控，后端的分析平台、数据库还得升级到能吃 128 位地址。这一圈升级里但凡漏一环——忘了开监控、软件版本不支持、为省钱没买 v6 分析模块——计费就只剩看得见 IPv4 了。

技术实践

核心思路：校外备一台双栈 VPS 当跳板，用校园网免费的 IPv6 通道和它建加密连接，之后所有流量都由它代出去。只有 IPv4 的目标，就靠 VPS 中转。

先判断校园网属于哪种

动手前先测，不然白忙。

看认证前有没有公网 IPv6。退出认证、别登录账号，看设备拿没拿到公网 IPv6：

开头是 2 或 3 的（2000::/3）才是公网地址，fe80:: 那种链路本地的不算。

再测通不通：

  • 认证前 IPv6 就能 ping 通、能上网 → 形态一，账号都不用登。
  • 认证前不通、登录后才通 → 接着测计费：登录后用 IPv6 拉个大文件（找个带 v6 的高校镜像站），再去自助服务查流量。IPv4 涨了、IPv6 那份没记上 → 形态二。

形态一：认证前直接用

最省事，账号都不用有，设备已经能出 IPv6 了，缺的只是「把流量都塞进 IPv6」这一步：

  • 目标站本身支持 IPv6（Google、YouTube、很多镜像站）→ 系统一般优先走 v6，直接就上了。
  • 只有 IPv4 的服务（大多数游戏、国内不少站）→ 得靠下面的 VPS 跳板中转。

形态二：认证后跑 IPv6

得有正常账号，先登录，登录后 v4/v6 都通、但 v6 不计费。用法就是把耗流量的活儿全压到 IPv6 上：代理/VPN 的出口连到 VPS 的 IPv6 地址，下载、看视频全过 v6，账单只涨那点 v4。

两种形态最后都落到同一件事：让流量走 IPv6 出去，只有 IPv4 的目标用 VPS 中转。

VPS 和代理怎么搭

跳板要求：

  • VPS 必须有 IPv6（双栈），而且校园网能 ping 通它的 IPv6。有些校园网/教育网的 v6 只在教育网内或国内可达，国外 VPS 的 v6 不一定通，买之前先想办法 ping -6 一下它的地址，通了再上。
  • 代理软件得能把出口连接走 IPv6。

代理用啥都行，能连 v6 就成：

  • Hysteria2：弱网速度猛、带伪装，服务端监听端口，客户端把服务器地址填 VPS 的 IPv6（或解析到 v6 的域名）即可。部署使用教程
  • Vless：VLESS + TLS/REALITY 这类，一样把 server 指到 v6。
  • WireGuard：想要整机 VPN、全流量走隧道，Endpoint 填 VPS 的 IPv6，简单直接。

关键就一句：客户端连 VPS 的那一跳必须走 IPv6，才吃得到免费/免认证的通道。

让流量真正走 IPv6

隧道建起来了，还得防着流量偷偷从 IPv4 溜走：

  • 代理开全局/TUN 模式，把不认代理设置的程序也兜进来。
  • 形态一里，为了别让任何流量走上收费的 v4，可以直接关掉 IPv4，或调地址选择策略让系统优先 v6（Linux 改 /etc/gai.conf，Windows 用 netsh interface ipv6 show prefixpolicies 看和调）。
  • 连上后开 test-ipv6.com 或查 ip.sb，看到的是 VPS 的地址就对了。

几个坑

  • DNS 泄漏/计费：DNS 查询要是走了校园 v4 或校园 DNS，一来可能计费，二来暴露你访问的目标。让 DNS 跟着隧道走，或者用 DoH。
  • IPv6 地址会变：SLAAC 隐私扩展下客户端的 v6 地址常换，别把规则写死在某个具体地址上；VPS 那端是固定的，不受影响。
  • 哪天就没了：这漏洞靠的是管理员疏忽，认证或计费一升级就堵上（就是前面那两种形态的演进），别当长期方案。
  • 形态二要账号：它只是不计费，不是免认证，账号该登还得登，别搞混。
