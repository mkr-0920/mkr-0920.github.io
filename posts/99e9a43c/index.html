docker-iptables

发表于2024-12-25|更新于2026-07-25|Linux

简介

Docker 在运行时会自动配置 iptables 以处理容器的网络流量和端口映射，本文对docker自动配置的防火墙规则进行说明

伪装

规则各部分的解释

  1. 2099: 这是匹配到该规则的包的计数器，表示当前已有 2099 个数据包匹配此规则。

  2. 136K: 这是匹配到该规则的字节计数器，表示当前已有 136K 字节通过此规则。

  3. MASQUERADE: 表示这是一个伪装（Masquerading）规则。伪装是一种动态 NAT（网络地址转换）技术，通常用于允许内部网络的设备通过一个公共 IP 地址访问外部网络。

  4. all: 表示此规则适用于所有协议（包括 TCP、UDP 等）。

  5. –: 这一部分通常用于分隔规则的匹配条件和目标动作，后面是匹配条件。

  6. *: 表示匹配所有输入接口。

  7. !docker0: 表示匹配所有不通过 docker0 接口的流量。docker0 是 Docker 创建的虚拟网桥接口，通常用于连接 Docker 容器。

  8. 172.17.0.0/16: 表示匹配源地址在 172.17.0.0/16 网段的流量。这是 Docker 默认的网络地址范围，通常用于 Docker 容器的内部网络。

  9. 0.0.0.0/0: 表示匹配目标地址为任意 IP 地址，意味着可以访问外部网络。

规则的作用：
对来自 172.17.0.0/16 网段（Docker 容器的内部网络）的所有流量进行伪装，且该流量不通过 docker0 接口（确保不是容器间通信）。这意味着所有从 Docker 容器发出的流量（不通过 Docker 的虚拟网桥）都将使用宿主机的公共 IP 地址进行伪装，以便能够访问外部网络。

规则各部分的解释：

  1. 0: 这是匹配到该规则的包的计数器，表示当前没有数据包匹配此规则。

  2. 0: 这是匹配到该规则的字节计数器，表示当前没有字节通过此规则。

  3. MASQUERADE: 表示这是一个伪装（Masquerading）规则。伪装是一种动态 NAT（网络地址转换）技术，通常用于允许内部网络的设备通过一个公共 IP 地址访问外部网络。

  4. tcp: 表示此规则适用于 TCP 协议。

  5. –: 这一部分通常用于分隔规则的匹配条件和目标动作，后面是匹配条件。

  6. *: 表示匹配所有输入接口。

  7. *: 表示匹配所有输出接口。

  8. 172.17.0.3: 表示匹配源地址为 172.17.0.3 的流量。这个 IP 地址通常是 Docker 容器的内部 IP 地址。

  9. 172.17.0.3: 表示匹配目标地址为 172.17.0.3 的流量。

  10. tcp dpt:5700: 表示匹配目的端口为 5700 的 TCP 流量。

规则的作用：
对来自 IP 地址 172.17.0.3 的 TCP 流量（目标端口为 5700）进行伪装。伪装的过程是将源地址替换为宿主机的公共 IP 地址，以便能够通过外部网络访问。

目标地址转换（Destination NAT）

规则各部分的解释：

  1. 42: 这是匹配到该规则的包的计数器，表示有 42 个数据包匹配了此规则。

  2. 2352: 这是匹配到该规则的字节计数器，表示总共传输了 2352 字节的数据。

  3. DNAT: 表示这是一个目标地址转换（Destination NAT）规则。用于将进入的数据包的目标地址更改为指定的地址。

  4. tcp: 表示此规则适用于 TCP 协议。

  5. –: 这一部分通常用于分隔规则的匹配条件和目标动作，后面是匹配条件。

  6. !docker0: 这个条件表示匹配所有不通过 docker0 网桥接口的流量。docker0 是 Docker 默认创建的虚拟网络接口。

  7. *: 表示匹配所有输入接口。

  8. 0.0.0.0/0: 表示匹配所有源地址。

  9. 0.0.0.0/0: 表示匹配所有目标地址。

  10. tcp dpt:5700: 表示匹配目的端口为 5700 的 TCP 流量。

  11. to:172.17.0.3:5700: 这是 DNAT 的目标，表示将匹配到的流量的目标地址转换为 172.17.0.3，目标端口为 5700。这通常是一个 Docker 容器的 IP 地址。

规则的作用：

  • 将所有不通过 docker0 网桥接口的 TCP 流量（目标端口为 5700）重定向到 IP 地址为 172.17.0.3 的 Docker 容器的 5700 端口。
  • 这通常用于实现端口映射，使得外部流量可以访问 Docker 容器内的服务。

转发（Forward）

前面的规则都在 nat 表里，负责地址转换。真正决定一个转发的数据包放行还是丢弃的，是 filter 表的 FORWARD 链。Docker 启动后会把 FORWARD 链的默认策略改为 DROP，也就是默认不允许任何转发流量，再通过自己创建的几条链来放行需要的流量。

规则各部分的解释：

  1. policy DROP: FORWARD 链的默认策略为 DROP，凡是没有被后面规则放行的转发流量都会被丢弃。

  2. DOCKER-USER: 把所有流量先交给 DOCKER-USER 链处理，这条链留给用户添加自定义规则，Docker 不会去动它。

  3. DOCKER-ISOLATION-STAGE-1: 把流量交给隔离链处理，用于隔离不同的 Docker 网络，防止它们互相通信。

  4. ACCEPT（out 为 docker0，ctstate RELATED,ESTABLISHED）: 放行目标接口为 docker0、且属于已建立连接或相关连接的流量。这样容器发出请求后，外部返回的响应包能够回到容器。

  5. DOCKER（out 为 docker0）: 把发往 docker0 的流量交给 DOCKER 链处理，端口映射的放行规则就在这条链里。

  6. ACCEPT（in 为 docker0，out 为 !docker0）: 放行从 docker0 进来、发往非 docker0 接口的流量，也就是允许容器访问外部网络。

  7. ACCEPT（in 为 docker0，out 为 docker0）: 放行从 docker0 进来又发往 docker0 的流量，也就是允许同一网桥下的容器互相通信。

规则的作用：
FORWARD 链是所有转发流量的入口。Docker 把默认策略设为 DROP，再按顺序把流量分发给 DOCKER-USER、DOCKER-ISOLATION-STAGE-1、DOCKER 等链，只放行响应流量、端口映射流量、容器访问外网以及容器间通信的流量，其余一律丢弃。

放行容器端口（DOCKER 链）

规则各部分的解释：

  1. 0: 包计数器，表示当前没有数据包匹配此规则。

  2. 0: 字节计数器，表示当前没有字节通过此规则。

  3. ACCEPT: 表示放行匹配到的流量。

  4. tcp: 表示此规则适用于 TCP 协议。

  5. !docker0: 表示匹配所有不通过 docker0 接口进入的流量，也就是来自外部的流量。

  6. docker0: 表示匹配输出接口为 docker0 的流量，也就是发往容器的流量。

  7. 0.0.0.0/0: 表示匹配所有源地址。

  8. 172.17.0.3: 表示匹配目标地址为 172.17.0.3 的流量，这是容器的内部 IP 地址。

  9. tcp dpt:5700: 表示匹配目的端口为 5700 的 TCP 流量。

规则的作用：
放行从外部接口进入、发往容器 172.17.0.3 的 5700 端口的 TCP 流量。这条规则和前面 nat 表里的 DNAT 规则是配套的：DNAT 负责把目标地址改写成容器 IP，DOCKER 链负责把改写后的流量放行，端口映射才能真正生效。

网络隔离（DOCKER-ISOLATION）

这两条链用于隔离不同的 Docker 网络，确保一个网络里的容器默认无法访问另一个网络。

规则各部分的解释：

  1. DOCKER-ISOLATION-STAGE-2（in 为 docker0，out 为 !docker0）: 从 docker0 进来、要发往其他接口的流量，交给 DOCKER-ISOLATION-STAGE-2 链继续判断。

  2. RETURN: 其余流量直接返回 FORWARD 链，继续走后面的规则。

规则各部分的解释：

  1. DROP（out 为 docker0）: 如果流量的目标接口又是某个 Docker 网桥，就直接丢弃，阻止跨网络访问。

  2. RETURN: 其余流量返回上一级链，继续正常转发。

规则的作用：
两级隔离链配合工作。第一级判断流量是否从一个 Docker 网桥发出并要去往别的接口，是的话就交给第二级；第二级判断目标是不是另一个 Docker 网桥，是的话就丢弃。这样就实现了不同 Docker 网络之间的隔离，而不影响容器访问外部网络。在只有默认 docker0 一个网桥的情况下，这两条链基本不起作用；一旦创建了自定义网络（会新增 br-xxxx 网桥），隔离规则才会真正发挥作用。

用户自定义（DOCKER-USER）

规则各部分的解释：

  1. RETURN: 默认只有一条 RETURN 规则，表示把流量原样返回 FORWARD 链，不做任何处理。

规则的作用：
DOCKER-USER 链在 FORWARD 链中位于所有 Docker 规则之前，Docker 重启或重建规则时都不会覆盖它。如果需要在 Docker 的规则之前加入自己的限制（比如只允许某些 IP 访问容器），就应该把规则加到这条链里，而不要直接改 FORWARD 链，否则容易被 Docker 覆盖。

数据包的处理流程

以外部访问容器 5700 端口为例，把前面的规则串起来看，一个数据包大致会经过这样的过程：

  1. 数据包到达宿主机，进入 nat 表的 PREROUTING 链，命中 DNAT 规则，目标地址由宿主机 IP 改写为容器地址 172.17.0.3:5700。

  2. 经过路由判断，发现目标不是本机，进入 filter 表的 FORWARD 链。

  3. 在 FORWARD 链里依次经过 DOCKER-USER、DOCKER-ISOLATION-STAGE-1，再由 DOCKER 链放行发往 172.17.0.3:5700 的流量。

  4. 数据包从 docker0 网桥转发进容器，容器上的服务收到请求。

  5. 容器返回的响应流量经过 nat 表 POSTROUTING 链的 MASQUERADE 规则，源地址被伪装成宿主机 IP，再发回给外部客户端。

这样，外部客户端全程只和宿主机的 IP、端口打交道，容器的内部地址对外是透明的。
